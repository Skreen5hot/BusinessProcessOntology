# BPO v0.4.0 moves to https://fandaws.com/ontology/bpo

Our acknowledgment said the namespace move would reach you as a message of its own, with the
mapping and the commit that lands it, before you need to act. This is that message. Nothing
breaks for you today: your pin on `6613194` is still reachable and its bytes are unchanged.

## The mapping: one base substitution

| Old | New |
|---|---|
| `http://example.org/apqc#X` | `https://fandaws.com/ontology/bpo#X` |
| `http://example.org/apqc/…` (scheme, shapes, perf, module ontology IRIs) | `https://fandaws.com/ontology/bpo/…` |

Local names are unchanged, so `ex:ActOfReporting` stays `…/bpo#ActOfReporting`. For the BCO's
extract, the change is the six genera's IRIs:

| Was | Now |
|---|---|
| `http://example.org/apqc#ActOfAcquisition` | `https://fandaws.com/ontology/bpo#ActOfAcquisition` |
| `http://example.org/apqc#ActOfDevelopment` | `https://fandaws.com/ontology/bpo#ActOfDevelopment` |
| `http://example.org/apqc#ActOfImprovement` | `https://fandaws.com/ontology/bpo#ActOfImprovement` |
| `http://example.org/apqc#ActOfOrganizationalEstablishment` | `https://fandaws.com/ontology/bpo#ActOfOrganizationalEstablishment` |
| `http://example.org/apqc#ActOfRemuneration` | `https://fandaws.com/ontology/bpo#ActOfRemuneration` |
| `http://example.org/apqc#ActOfReporting` | `https://fandaws.com/ontology/bpo#ActOfReporting` |

The prefix label in BPO's Turtle is still `ex:`. A later BPO phase renames it to `bpo:`. That
rename changes no IRI, so it will not need another re-pin.

## What else changed in `apqc-ext.ttl`: nothing

BPO checked that the file's graph at `327ea2c`, ignoring `owl:versionInfo`, is isomorphic to its
graph at `6613194` with the base rewritten. The definitions, anchors and CCO/BFO ancestry are the
same, so an extract taken under the mapping should equal your current extract with the base
rewritten. The CCO pin is unchanged (v2.0, 2024-11-06).

## Not covered

Nothing serves the ontology at these IRIs on fandaws.com yet. That is separate work. For now the
IRIs are names, and the raw GitHub URL at the pinned commit is still the place to fetch from.

An acknowledgment once the BCO has re-pinned would close the loop, but nothing here requires one.
